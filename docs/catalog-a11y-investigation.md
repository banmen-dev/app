# 見本カタログの axe の時間切れ（#1237）

## 失敗した trace

2026-11-15 に、[main の CI run 43617710785](https://github.com/banmen-dev/app/actions/runs/43617710785) の `e2e-dev (2)`、成果物 `e2e-dev-2-attempt-1`（ID `14123680680`）を調べた。対象コミットは `5f9ea485` で、結果生成の削減と上限120秒化を行った PR #1230（`f9f75e3`）より前の trace。`390px / simple_dark` の `trace.zip` の `test.trace` と `1-trace.trace` を照合した。

| 区間 | test.trace の開始・終了（ms） | 所要時間 |
| --- | --- | --- |
| カタログへの遷移 | 258766.663–260437.499 | 1.67秒 |
| 遷移開始から全セクションの表示確認完了 | 258766.663–284929.205 | 26.16秒 |
| テーマの適用 | 284929.873–285638.008 | 0.71秒 |
| axe の開始から結果集約完了 | 285638.878–321081.931 | 35.44秒 |

axe 内では `runPartial` が20.29秒、結果の転送の `chunkResults` が3.56秒、`finishRun` が9.63秒を占めた（上の表と同じテスト側の時刻。ブラウザ側の実行時間だけではなく通信・記録も含む）。結果集約の途中で60秒の上限に達し、終了処理の開始後に集約が完了している。検査の違反による失敗ではない。

表示確認は54件の目次に対して `getAttribute` と `toBeVisible` を逐次実行していた。遷移後の確認だけで約24.49秒かかる。多くの呼び出しが約0.2秒かかり、ブラウザとの往復と trace 記録が積み重なっている。テーマ適用の待ちが主因ではない。ジョブ末尾のサーバー監視も、1秒以上の遅れや想定外の応答を0件と報告している。

## 修正

先行の [PR #1230](https://github.com/banmen-dev/app/pull/1230) は axe の結果生成を違反・保留に絞り、テスト上限を120秒に変更した。#1237 ではさらに、目次の参照先とセクションの ID をそれぞれ一括取得し、1対1の対応を比較する。全セクションの表示は `:visible` の件数を自動再試行付きの assertion で確かめる。目次が空、不正な参照先、対応しないセクション、非表示のセクションを拒む回帰テストも追加する。

テスト上限は60秒に戻す。WCAG の規則、全テーマ、両画面幅、カタログ全体の axe 検査と、各 assertion の待ちは維持する。見本の内容とデザインは変えない。

## 検証

修正後の実際の所要時間と安定性は、PR の CI の `e2e-dev` と `e2e-repeat`（5回）で確認する。以前の内訳から逐次確認の約24.49秒を除いた約38秒は、少数の往復に置き換えた場合の概算にすぎず、先行修正の効果や実行間の揺れを測ったものではない。全テーマ・両幅で60秒の上限を維持した全件成功を必要条件とし、各テストの所要時間と繰り返しの最大値を記録する。trace からの時間配分は原因調査であり、修正後の測定値としては扱わない。
