## 条件

B は現行の `sprint-list` → `plan-summary` の並列開始と両応答の待ち。C は同じ順で両方を開始し、`sprint-list` の応答で一覧を利用可能にし、`plan-summary` が返り次第集計を表示する。どちらも計測専用の本番ビルドを使う。画面の変更案は [Issue #1057](https://github.com/banmen-dev/app/issues/1057) の合意を参照。 [PR #1253 の API 診断](plan-loading-comparison-results.md)

| 経路 | 起点 |
| --- | --- |
| URL直接表示 | 新しいブラウザコンテキストで文書を開く navigation start。 |
| 画面内遷移 | 同じワークスペースのバックログの計画リンクで実際にクリックが発生した時点。温めと記録の各試行はブラウザの戻る操作でバックログに戻って準備する。 |
| app:sprints の再読み取り | 表示済みの計画で `invalidate('app:sprints')` を起動した時点。 |
| app:backlog-tree の再読み取り | 表示済みの計画で `invalidate('app:backlog-tree')` を起動した時点。 |

#1253 の履歴ありの架空データを一般メンバーで使用した。タスク5,000件、エピック10件、ストーリー100件、進行中1スプリントと未完了30件、終了3スプリントを含む。このデータから、先のスプリントを追加した「先のスプリントあり」と、書き込み不可の「終了済み」を用意し、同じ組織の「空」も含めて4条件とした。固定のデータの基準日は2026-11-22。

- 一覧表示は同じ世代の対象レーンとタスクの行、または空の一覧が描画された時点。空の一覧の表示と、集計成功を確認した結果の空状態は別に測る。
- 操作開始は、対象操作が表示され有効になったことを確認した最初の描画フレーム。画面内ではコントロールの中央が入力を受けることを当たり判定する。一覧と集計は2フレーム連続で成立した時点を記録するため、操作開始が一覧表示より1フレーム程度早く出ることがある。方式 B/C には同じ指標定義を適用した。編集可能な一般メンバーは「バックログから入れる」、終了済みはタスク詳細の閲覧リンクを対象とした。画面外のコントロールは当たり判定を省き、計時後にスクロールと試行クリックで確認した。その値はスクロールを含むクリック到達時間と区別する。空では適用外。
- 集計表示は、同じ世代の見出しの集計、ベロシティ、対象レーンの積載量、エピックの残りが描画された時点。空では集計が成功して空の状態が確定した時点。親などの通信は開始・転送完了を記録した。一覧・集計 API は `callOperation` が JSON 読み取りを終えた時刻を別に取り、ページの `load` 復帰直前も記録した。
- 各条件で温め2回・記録20回を独立2巡。各巡は同じデータから作った使い捨て D1 を使い、2巡目は方式・データ・経路の実行順を反転した。固定の 1280×900、日本語、Asia/Tokyo、Chromium とローカル Worker、ループバックの gzip 配信。HTTP キャッシュ、SvelteKit の先読み、サービスワーカーを無効にした。
- 全試行で両 API の発行順と回数を確認し、計時後に応答を回収して HTTP・出力スキーマと画面の例外を確認した。人工遅延と書き込みを伴う確認は計時を終えた後に行った。

## 再現と再集計

新規計測は、データの基準日と実行日の関係が2026-11-22の計測時と同等であることを確認する。Worker と Chromium は実時計で動く。2026-12-05（日本時間）の進行中スプリントの期日を過ぎると期限超過の表示が出る。実行日が離れるとベロシティの集計対象も変わり得るため、その場合の新規計測はここにある試行と別条件として扱う。保存した生データからの再集計は実行日に依存しない。

```sh
pnpm exec node scripts/plan-loading-browser-bench.ts --output /tmp/plan-loading-browser-new.json
pnpm exec node scripts/plan-loading-browser-summary.ts /tmp/plan-loading-browser-new.json /tmp/plan-loading-browser-new-summary
```

出力先は未作成のファイル名を使う。Chromium は Playwright の配布版を用意するか、`--chromium` に実行ファイルを指定する。配信・Worker・inspector に9774〜9776を使う。計測器はローカルの使い捨て D1 と専用設定で起動し、終了時に停止・片付けを行う。既存の `build/` がある場合は復元する。

```sh
gzip -dc docs/plan-loading-browser-samples.json.gz > /tmp/plan-loading-browser-recorded.json
pnpm exec node scripts/plan-loading-browser-summary.ts /tmp/plan-loading-browser-recorded.json /tmp/plan-loading-browser-recorded-summary
```

[生データ](plan-loading-browser-samples.json.gz) と [採否・全セルの集計](plan-loading-browser-decision.json) を保存した。分位点は nearest-rank。20件の p95 は昇順19番目で、採否は丸め前の値を使う。ローカル Worker/D1 とループバックでは、処理順や同時実行が実運用と異なる可能性がある。数値基準を満たしても、これらの影響を切り分けられない場合は、実運用に近い隔離環境で確認してから判断する。
