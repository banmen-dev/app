# 画面の採点

進行役が渡した左右の比較画像、演出の連続コマ、撮影時の `design-rules.md`、テキストの除外一覧だけを読む。`design-rules.md` が読めなければ採点せずに、その理由を返す。同じ状態の全テーマと両方の幅を見て判定する。画像の判別に必要な資料が欠けていたら、該当する条件と理由を未判定として返す。見本側に「フォント未確認」とあれば、書体や文字幅の差は未判定として返す。

渡された `design-rules.md` を全部読み、それに照らして、次を観点ごとに1〜10点で採点する。規則を満たし実用上の問題が無ければ8点以上、直す必要があれば7点以下とし、利用を妨げるほど点を下げる。演出が対象に含まれないときは対象外と記す。

- 見本との一致。部品の形、余白、情報の並びと強弱を見る。名前、件数、数値などの例データの違いは評価から外す。
- 文字の読みやすさ。はみ出し、重なり、切れ、読みづらい折り返しを見る。
- 色と状態。色の役割、状態を形や言葉でも示しているかを見る。
- 狭い幅。スマホで読む順序、主要な操作の置き場所、枠と内容の崩れを見る。
- 演出。短く1回で終わり、最後のコマで状態や知らせが読めるかを見る。

各観点について点数、根拠になった画像名、画像で確かめたことを表で返す。複数の条件に問題がある場合は一番悪かった条件を根拠にする。悪い順に最大3件、各指摘に画面・状態、テーマ・幅、画像名と箇所、見えている問題、直し方を添える。同じ問題を複数テーマで見つけた場合は1件にまとめ、該当する条件を並べる。見本でも同じ箇所に問題がある場合は「見本にもあり」と記す。

除外一覧に原因のコードのパスと判断理由があり、指摘と条件が一致したものは点数と上位3件から外す。根拠の記載は一覧で確認し、コードは開かない。採点表とは別に、適用件数（0件も明記）、適用した各件の条件・内容・根拠、適用しなかった項目と理由を返す。
