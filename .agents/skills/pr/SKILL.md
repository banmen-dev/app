# pr（Codex）

最初に `AGENTS.md` と [共通の読み替え](../README.md) を読む。
[共有する手順](../../../.claude/skills/pr/SKILL.md) を読み、次の Codex 向けの扱いを優先して進める。

対象 PR の状態から原本の `create.md`、`feedback.md`、`merge.md` の必要な工程だけを読む。`done-check` は Codex 用を使う。E2E の事前実行を PR 作成条件にしない。CI の `e2e`、`e2e-dev`、`e2e-repeat` の結果を確認し、未実行・未確認は区別して報告する。

## Codex で CI とレビューを監視する

PR を作成または再開したら、その PR の状態、head SHA、CI、レビュー、コメントとスレッドの状態を取得する。通知で同じセッションを再開できる購読機能が使える場合は登録する。使えない場合は、`gh api` または GitHub のツールで30〜60秒おきに状態を確認する。`feedback.md` の待ち時間と停止条件に従う。`ci-ok` がまだ出ていなくても、対象 head の CI や必要なジョブが進行中なら、実行の状態と設定されたタイムアウトを見ながら監視を続ける。

push のたびに送った SHA を記録する。PR の最新 head がその SHA またはそのコミットを含む後続の SHA になったことを確認してから、その head の `ci-ok` と必須チェックで CI を判定する。レビューは `feedback.md` に従い PR 全体の指摘と実行履歴から確認する。失敗・コンフリクト・指摘を処理したら同じ確認に戻る。取得に失敗した場合は、承認範囲と作者の扱いを満たす読み取り手段に切り替え、確認できない状態は未検証とする。

`make` から進める場合は、CI・レビューへの対応を確認して6行のレポートを返し、監視を終える。監視中に PR がマージされた場合は、マージされた PR の head の `ci-ok` の結果を確認して報告する。停止条件に当たった場合も含め、監視を終えるときは登録した購読を解除する。マージやその後の片付けは別途依頼されたときに進める。
